# 输入浮层与键盘手势：通用实现经验

浏览器半侧插件里「在输入框上方开浮层、跟键盘打交道」这一类交互的通用经验。
覆盖：双击/组合手势的判定、过滤列表浮层的自绘守则、内容可编辑宿主的异步写入、
浮层生命周期、DOM 归属核对、类型依赖缺口、以及全新实例自动化首启。
具体 API、插槽名与版本行为仍以目标运行时源码为准。

## 一、双击手势判定：纯时间窗，不做按键序列匹配

「双击 Esc」「双击 Ctrl」这类手势**不用按键序列（chord）匹配**实现，而是记时间戳：
两次按下间隔 ≤ 窗口 且 上一次定时器仍在，才算双击。两条件缺一不可——后者保证超时后
第一次按下不残留「半开」状态。

可对标的成熟数值（据公开源码/文档）：

| 实现 | 窗口 | 特点 |
|---|---|---|
| Claude Code 双击 Esc | 800 ms | 第一键透传、第二键消费；窗口内再按第三键需重新起算 |
| pi 扩展 | 500 ms | 第三方类比，声称与 Claude Code 一致但实际数值不同 |
| Codex 回滚 | 无窗口（状态机） | 只有「按了别的键」才作废——误触投诉多，不学 |

判定要点：

1. **第一键透传不消费**：单按仍要触发宿主原有行为（关工具栏、取消组字等），只记时间戳。
2. **第二键必须消费**（preventDefault + stopPropagation）：浮层是同步打开的，不消费的话
   第二次按键会立刻落到刚打开的浮层上把它关掉——用户看到的是「闪了一下」什么都发生。
3. **任何其他按键、失焦、会话切换都清零待定状态**，否则上一次按下会一直挂着等配对。
4. **用单调钟**：`performance.now()`，不要用 `Date.now()`（会被系统校时、时区切换反向影响）。
5. **组字中停顿**：`isComposing` 或 `keyCode === 229` 的按键既不推进时间戳也不消费，
   完全交给输入法——否则中文用户无法用 Esc 取消组字。
6. 手势必须**可配置关闭**。把双击绑死在用户天天按的键上（vi 用户的 Esc）而不可关，
   会变成投诉根源；给一个开关/枚举，行为要立即生效。

## 二、输入框上方过滤列表：焦点留输入框，就必须自绘浮层

需求形态：焦点留在输入框、继续打字即过滤、↑↓ 只动高亮不动草稿、Enter/Tab 回填、Esc 还原。

**宿主 Menu 用不了**：它的方向键行走会把真实焦点搬进列表（并要求焦点在 anchor/列表内），
一旦焦点被抢走，打字过滤立刻失效。这类交互只能是手写浮层（fixed + document.body portal），
键盘监听留在输入框侧自己处理。

自绘列表的无障碍与交互底线：

1. **ARIA 结构**：容器 `role="listbox"`（或 list），每行 `role="option"`，行上 `aria-selected`，
   容器上 `aria-activedescendant` 指向当前高亮行 id。不要用平行 class 表达选中态。
2. **高亮跟随滚动**：重绘后对高亮行 `scrollIntoView({ block: 'nearest' })`，让选择永远可见。
3. **查询词从草稿推导，不逐键累加**：输入法组字期间浏览器不发 `keydown`，逐键累加永远攒不到汉字。
   打开时记下原文（origin），草稿变化时比对：草稿以 origin 开头则增量部分是查询词；
   删到 origin 以内则查询词归零，继续删视为改草稿本身。过滤后回到第一条，避免停在越界高亮上。
4. **浮层打开时，宿主的「打开建议菜单」类监听要让位**：否则取消浮层还原出的草稿
   （以 `/`、`@` 开头等）会再次弹出建议菜单，把你的浮层顶掉并再也关不掉。
5. **方向键修饰符语义**：列表按最新在上渲染时，↓ 是更旧、↑ 是更新；Home/End 跳首尾。
6. 长条目**单行省略**（`text-overflow: ellipsis`），行上 `title` 属性承载全文悬停。

## 三、内容可编辑宿主的草稿写入是异步的

Lexical/ProseMirror 这类内容可编辑宿主，`setDraft` 之后立刻放光标会被内部重渲染覆盖。
正确姿势：写入草稿后 `requestAnimationFrame` 里再 `focus()` + `setCaretAt(len)`。
回填、取消还原一律走宿主的 `inputActions` 类接口，不要直接改 DOM——宿主的
粘贴、chip、图片管线都挂在它自己的写入路径上。

## 四、浮层生命周期：卸载必须销毁

浮层节点挂在 document.body 上，React 卸载、会话切换、热重载都不会自动清它。
后果是 body 上留孤儿节点：看不见但拦截点击、消耗内存。

- 卸载 cleanup 里必须销毁浮层（幂等 remove）。
- 会话切换 / 会话删除 / phase（提交、生成中）变化时强制关闭并清状态。
- 每次验证都断言 DOM 计数归零，不止「界面上看不到了」。

## 五、DOM 归属核对：别把宿主的元素当成自己的

排查「右边这个是不是我画的」这类问题时，别凭截图印象下结论：

- **整页扫你的类名前缀**（`[class*=你的前缀]`），列出每个命中元素的坐标与文案，
  证实哪些元素真是你的；否则「宿主在宽屏下自动开的空面板」这类元素很容易被算到你头上。
- **宿主 DOM 标记（data-*、类名）只要未文档化，就会在版本间消失或改名**。
  依赖某个标记做选择器之前，先运行时抓一份真实属性清单核对；不要拿旧版本的记忆去赌。

## 六、类型缺口：peer 包的类型传递依赖不在自己依赖树

peer 声明的官方包可能引用另一个官方包的**类型**（如某 hook 的类型来自其传递依赖）。
该传递依赖不在你的依赖树时，tsc 报的往往不是「找不到模块」，而是隐式 any 一类
（`TS7006 Parameter implicitly has an 'any' type`），指向你完全没动过的选择器参数。

- 判定：报错行看起来「明明有类型却变成 any」，先看它来自哪个 peer 包，再顺着 import 链
  找缺的传递依赖包名。
- 修法：把缺失包**显式装进 devDependencies**（版本与 peer 声明一致）。
- 收尾：装完 `git checkout -- package.json` 还原清单（pnpm 会顺手重排依赖顺序）。

## 七、全新实例自动化首启：先点掉引导模态

全新 profile 首次打开通常有固定引导模态（如「预览版说明」）遮住整页，不是偶发遮罩。
自动化脚本要先 `[role=dialog]` 定位并点掉「继续」类按钮，再继续后续点击，
否则所有真实点击都被那层拦截。判断是否新的 profile：本次会话看没看过该模态即可。
