# 补丁、打包与发布

## 分层验证

按顺序验证：静态结构、构建产物、实际 tarball、目标运行时、外部发布真源。

- 补丁可解析不等于插件已挂载。
- 安装成功不等于依赖和入口可用。
- 工作区代码可运行不等于 tarball 完整。
- 发布命令成功不等于 registry 提供了正确版本。

## 补丁

先明确加载层级、覆盖方式和整体替换语义。配置对象是否深合并不能凭直觉判断；动态表达式、凭据引用和权限范围必须回到目标运行时核验。联调优先使用临时 profile 或临时 overlay，避免污染生产配置。

## 包体验证

检查入口导出、exports、客户端入口、本地化资源、图标、补丁和依赖声明。使用打包清单命令读取实际文件，再在临时干净目录安装 tarball 并加载。

## 发布后

从独立 registry API、dist-tag、下载 tarball 和干净环境安装结果回读版本与内容。版本、能力描述、入口文档和包清单必须一致。涉及 push、publish 或永久 profile 修改的操作，都要有明确权限和回滚路径。
