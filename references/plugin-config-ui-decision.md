# 插件自有配置界面的选型：自有存储还是 Settings 集成

本文是 [plugin-config-card-architecture.md](./plugin-config-card-architecture.md) 的决策补充。前文讲机制，本文讲怎么选。

## 一、先回答一个常见误解

「DSH 提供了 Settings 系统，插件配置就应该交给它」——这个判断不成立。Settings 的可写能力只覆盖 volatile 进程内活值，而大多数插件需要持久化用户配置。

选型前必须先回答：这个配置重启宿主后需要保留吗？

- 需要保留 → 持久化配置 → Settings 写不了 → 走自有存储。
- 不需要保留 → 进程内偏好 → 可以走 Settings volatile。

这一条判定直接决定后续所有工作。跳过它会做出一个「能显示但写不进去」或「能写但重启丢」的界面。

## 二、三种实现形态

| 形态 | 界面显示 | 写入是否生效 | 重启后保留 | 冲突保护 |
|---|---|---|---|---|
| 自有端点 | 是 | 是 | 是 | 通常无 |
| Settings 集成（持久化字段） | 是 | **否，抛错** | 是 | 有 |
| Settings 集成（volatile 字段） | 是 | 是 | **否** | 有 |

表格第二行是最危险的组合：界面看起来完全正常，用户点击后失败，且失败发生在异步写入里，界面上不一定有可见提示。

## 三、卡片消费的四种数据

现实中的配置卡片通常不是单一数据源。按性质拆分后每类各走各的路，是正常设计而不是妥协。

```text
持久化配置    →  自有端点写入，回读确认落盘
进程内偏好    →  Settings volatile（若已集成）
运行时推导值  →  只读端点，读取时实时计算
动作          →  命令式端点，返回最新状态
```

运行时推导值为什么不能当配置：它由多层来源按优先级合并得出，中间任一层变化都会改变结果。把它写进配置层，等于让缓存永久盖住真值。

典型例子是多层优先级链（环境变量 > 运行时补丁 > 配置文件 > 内置兜底）。环境变量只有进程重启才变，若把它的值落盘，下次启动会读到过期的落盘值，反而盖住新的环境变量。

## 四、Settings 集成的真实收益与代价

收益（仅在走 volatile 或混合时成立）：

- 统一的 schema 校验与表单渲染语义。
- 写入串行化与 revision 冲突检测：多个页面同时改同一配置不会互相覆盖。
- 命名空间消失时自动卸载对应界面（`whileServed` 的 disposer）。
- 插件卸载后配置界面自动清理，无需自建生命周期。

代价：

- 持久化字段写不进去，必须另建落盘路径。
- 落盘位置与插件原有配置文件可能不同，需要明确唯一真源。
- volatile 引用在宿主重启时的初值来源需要显式定义，否则会静默回到默认值。
- 多出一条「表单写入 → 引用更新 → 落盘」的同步链路，每一环都可能失败。

判据：**当配置面板没有任何用户可感知的收益变化，而持久化路径上多出一条失败链路时，不要迁移。**

## 五、迁移前的否决条件

出现以下任一情况，直接不迁移，保留自有实现：

1. 迁移后界面视觉与交互完全不变。
2. 卡片的主要数据是运行时推导值。
3. 插件已有一套落盘路径且稳定，迁移需要新增第二条。
4. 现有实现已通过行为测试与产物断言。
5. 迁移需要把持久化字段改成 volatile 才能跑通。

迁移值得做的条件，通常是同时满足：

- 新架构带来用户能感知的能力（例如真正的冲突保护、跨页面同步）。
- 迁移不引入新的持久化链路，或新增链路可被自动化测试完全覆盖。
- 原有实现确实存在已知缺陷，而非仅「不够优雅」。

## 六、若决定迁移：最小可行路径

1. 先只迁移一类数据，挑风险最低的那类。
2. 每类数据独立接线，不要一次全切。
3. 为新增的每一跳补一条可失败测试：写入失败、并发写、崩溃恢复。
4. 保留旧路径一个版本作为回退，观察真实使用后再决定是否移除。
5. 真机验证必须包含「重启宿主后配置仍生效」这一条，这是 volatile 方案唯一的致命失败点。

## 七、验收清单

迁移或保留都要逐条证明，不接受「界面能看到」作为完成标准：

- 静态断言：产物中只出现允许的插槽名，配置卡 key 与声明一致。
- 服务断言：宿主命名空间注册存在，运行时可读到。
- 写入断言：真实点击一次写入，回读持久层确认落盘。
- 重启断言：重启宿主后配置仍然生效。
- 冲突断言：两个页面同时改同一配置，验证行为符合预期。
- 卸载断言：禁用或卸载插件后，配置界面消失且不留残影。

卸载断言经常被跳过。运行中的插件若留下旧界面，用户会以为配置还在生效。
